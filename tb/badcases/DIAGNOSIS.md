## 00_healthy：基线（正常该长什么样）

**配置**：3 层 ReLU MLP，SGD，`lr=0.05`，200 步。

```
loss      0.729 → 0.371 → 0.171 → 0.112 → 0.086      0/200 步出现上升
gradnorm  0.40  → 0.37  → 0.20  → 0.12  → 0.086      单调缓降
|W_fc01|  4.47  → 4.71                                缓慢增长
```

**在 TensorBoard 里**：所有曲线都是**平滑的**，没有任何一步的突然跳变；`DISTRIBUTIONS` 里
`weights/fc01` 是一条**缓慢右移、宽度基本稳定**的亮带。

**为什么算健康**：每步更新量 `lr × |grad| ≈ 0.05 × 0.4 = 0.02`，远小于参数本身的尺度（4.5），
所以是在"小步稳定下山"。梯度随 loss 一起下降，说明还没到平台期也没塌陷。

## 01_vanishing：梯度消失

**和基线差在哪里**

```python
# 基线：3 层 ReLU
nn.Linear(4, 64), nn.ReLU(), nn.Linear(64, 64), nn.ReLU(), nn.Linear(64, 2)

# 本案：20 层 Sigmoid，初始化 std 还很小
lin = nn.Linear(4 if i == 0 else 32, 32)
nn.init.normal_(lin.weight, std=0.05)   # ← 初始化太小
layers += [lin, nn.Sigmoid()]           # ← Sigmoid 导数最大只有 0.25
```

**实测**

```
loss      0.695 → 0.693 → 0.693 → 0.693 → 0.693     卡在 ln2（等于瞎猜）
gradnorm  0.13  → 4.5e-7（第 50 步就已经塌了）
fc01      0.000e+00  → 0.000e+00                    第一层梯度恒为 0
fc20      4.7e-8                                    最后一层也几乎没了
|W_fc01|  0.5579 → 0.5579                           权重一动不动
```

**在 TensorBoard 里看**

- `gradnorm/total`：切 **log 轴**，一条直线往下坠，从 1e-1 掉到 1e-7
- `gradnorm/fc01` 和 `gradnorm/fc20`：前者贴 0，后者还有 1e-8 —— **跨层差 8 个数量级**
- `loss/train`：完全水平，看起来"很稳定"，其实是**完全没学**
- `DISTRIBUTIONS` → `weights/fc01`：一条**纹丝不动的竖线**

**为什么会这样**：Sigmoid 的导数 `σ'(z) ∈ (0, 0.25]`，20 层连乘 ≤ `0.25^20 ≈ 9e-13`；
再乘上小初始化（std=0.05），梯度还没传到第一层就归零了。**前面的层收不到信号 = 永远不更新。**

**修法**

```python
# 1. 换激活 + 正确初始化
nn.Linear(32, 32), nn.ReLU()   # 配 kaiming_uniform_（PyTorch 默认就是）
# 2. 加归一化
nn.Linear(32, 32), nn.BatchNorm1d(32), nn.ReLU()
# 3. 加残差（深层必须）
out = x + block(x)
# 4. 简单粗暴：别堆 20 层
```

**真实场景**：很深的普通 MLP、老式 RNN/LSTM 堆叠、用了 sigmoid 门控且初始化不当的网络。

## 02_exploding：梯度爆炸

**和基线差在哪里**

```python
opt = torch.optim.SGD(model.parameters(), lr=10.0)   # 基线是 0.05，这是 200 倍
```

**实测**（跑满 300 步；这个模型**不会 NaN**，但已经彻底废了）

```
loss      0.729 → 0.214 → 6.19 → 610.6 → 1592.98（峰值） → 2.99 → 2.79 → 卡死 2.79
gradnorm  0.40  → 385.10（峰值，step 4） → 之后稳定在 0.69 附近
|W_fc01|  4.47  → 223.74                            权重涨了 50 倍
loss 上升次数：149/299                               一半的步在上升（在 2.1 和 2.79 之间来回）
```

注意：**300 步跑完都没有 NaN**。NaN 是更严重的情况（更深的网络、混合精度、ln/log 之类）才会出现；
这里表现是"冲高 → 卡死在比初始更差的水平"，同样不可用。

**在 TensorBoard 里看**

- `gradnorm/total`：**数量级尖峰**（0.40 → 385，step 4 一脚踩到底），之后回落到 0.69 附近
- `loss/train`：先冲到 **1593**（step 4），再回落到 2.8，然后就是一条水平线卡死
- 曲线不会断（没有 NaN），但会**卡在 2.1~2.8**，比初始的 0.73 更差
- `DISTRIBUTIONS`：权重分布被拉成极宽的一道

**为什么会这样**：更新量 = `lr × grad`，lr=10 时一步就把参数推到很远；参数变大 → logits 变大 →
softmax 饱和 → 梯度反而更大 → 正反馈，直到参数被推到很远的地方，训练再也回不来。

**修法**

```python
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)   # 最有效的一招
opt = torch.optim.SGD(model.parameters(), lr=0.05)        # 降回来
# 还可以：加 warmup、输入标准化、换 Adam（自适应步长更稳）
```

**真实场景**：大 lr 起步、没有归一化的深层网络、RNN、混合精度下的 loss scaling 配错。

## 03_oscillating：震荡不收敛

**和基线差在哪里**

```python
opt = torch.optim.SGD(model.parameters(), lr=2.0)   # 40 倍
batch_size = 32                                     # 小 batch，梯度噪声大
x, y = make_data(xor=True)                          # 换成 XOR 型标签，更难
```

**实测**

```
loss      0.716 → 0.507 → 0.123 → 0.192 → 0.498    最低摸到过 0.009，但又弹回去
gradnorm  0.29  → 0.42  → 0.37  → 0.56  → 1.12
loss 上升次数：132/300                              44% 的步在上升
|W_fc01|  4.47  → 12.79                            权重被推大了近 3 倍
```

**在 TensorBoard 里看**

- `loss/train`：**锯齿状**，不是平滑下滑；整体趋势几乎水平
- `gradnorm/total`：上下乱窜（0.3 ~ 2.0），没有收敛的下降趋势
- 和 `00_healthy` 勾在一起对比最明显：一条锯齿、一条平滑

**为什么会这样**：步长超过了损失曲面的曲率半径，每次更新都**越过谷底**到对面，来回弹。
小 batch 又放大了梯度噪声，让方向更不靠谱。

**修法**

```python
lr = 2.0 / 10            # 先降一个数量级
batch_size = 256         # 或增大 batch，降低梯度噪声
# 进阶：warmup（前 500 步线性升 lr）+ cosine 衰减；或直接换 Adam
```

**真实场景**：finetune 时忘了把 lr 调小、大模型配小 batch、分布式训练时 lr 没按卡数缩放。

## 04_frozen：权重冻结（最危险的一个）

**和基线差在哪里**

```python
# 基线
opt = torch.optim.SGD(model.parameters(), lr=0.05)

# 本案：只把最后一层交给优化器
opt = torch.optim.SGD(model[-1].parameters(), lr=0.05)
# 启动时会打印：优化器管着 2 个参数张量，模型一共 6 个
```

**实测**

```
loss      0.729 → 0.573 → 0.480 → 0.419 → 0.376     单调下降！0/200 步上升
gradnorm  0.40  → 13.0  → 30.5  → 52.6  → 77.0       涨了 190 倍
fc01      0.064 → 2.59  → 6.79  → 12.6  → 19.1       梯度越来越大
|W_fc01|  4.4720 → 4.4720                            ★ 一位小数都没变
```

**在 TensorBoard 里看**

- `loss/train`：**看起来是这批案例里最健康的一条** —— 单调下降、没有毛刺
- 但 `gradnorm/fc01`：一路**往上**涨（0.06 → 19），和所有正常案例相反
- `weights/fc01`（DISTRIBUTIONS）：11 个时刻的直方图**完全重叠**，一条死竖线
- 对照 `00_healthy`：同样 200 步，`|W|` 从 4.47 涨到 4.71

**为什么会这样**：前两层不更新，只有最后一层在学。为了拟合，最后一层的权重越来越大，
于是回传到前两层的梯度也跟着越来越大 —— 但**梯度并没有被用来更新它们**。
这就是「有梯度 ≠ 在学」。

**修法**

```python
opt = torch.optim.SGD(model.parameters(), lr=0.05)   # 传全部参数
# 自检：训练前打印一句
n_opt = sum(len(g["params"]) for g in opt.param_groups)
n_all = len(list(model.parameters()))
assert n_opt == n_all, f"优化器只收了 {n_opt}/{n_all} 个参数张量"
```

**真实场景**：只把 `model.encoder.parameters()` 传进去；自己 new 了一个参数但没换成
`nn.Parameter`；`requires_grad=False` 忘了改回来；LoRA/冻结策略写错。

## 05_dead_relu：神经元全死

**和基线差在哪里**

```python
with torch.no_grad():
    model[0].bias.fill_(-100.0)      # 让所有 ReLU 的输入都是负数
```

**实测**

```
loss      0.693 → 0.693 → 0.693 → 0.693 → 0.693     恒定 ln2，等于瞎猜
gradnorm  2.0e-2 → 3.3e-3 → 5.2e-4 → 8.4e-5 → 1.3e-5   只有最后一层 bias 还在动
fc01      0.000e+00 恒为 0
|W_fc01|  4.47 → 4.47                               不动
```

**在 TensorBoard 里看**

- `gradnorm/total`：从**第 0 步**就是 1e-2 量级，然后单调衰减到 1e-5
- `gradnorm/fc01`：恒 0（ReLU 导数是 0，梯度根本传不过去）
- `loss/train`：一条水平线
- `DISTRIBUTIONS` → `weights/fc01`：从第一次记录起就是**一条细竖线**

注意和 `01_vanishing` 的区别：本案是**一开始就死**（第 0 步 fc01 = 0），
消失是**逐步塌陷**（第 0 步 fc01 还有 6.4e-2）。

**为什么会这样**：`ReLU(x) = max(0, x)`，输入恒为负时输出恒 0、导数恒 0。
一旦某个神经元的输入长期为负，它就**永久死亡**（梯度为 0，再也不可能被拉回来）。

**修法**

```python
nn.LeakyReLU(0.01) 或 nn.GELU()        # 负区间不归零
nn.init.kaiming_uniform_(w, nonlinearity="relu")   # 正确初始化
# 真实场景里最常见的诱因是 lr 太大，先降 lr；加 BatchNorm 也能缓解
```

**真实场景**：大 lr 起步一把打死一片神经元（学习率 1e-1 以上常见）、输入没归一化、
weight decay 过大、初始化偏置不当。

## 从曲线到病因：速查表

| 你在 TB 里看到 | 第一怀疑 | 到第 4 节哪一案对照 |
|---|---|---|
| `loss` 水平线 + `gradnorm` 塌陷到 < 1e-6 | 梯度消失 | 01_vanishing |
| `loss` 水平线 + `gradnorm` **从第 0 步**就 ≈ 0 | 死层 / 参数没进优化器 | 05_dead_relu |
| `loss` 水平线 + `gradnorm` 正常 | 数据或标签有问题 | （本批没做） |
| `loss` 冲高 + `gradnorm` 数量级尖峰 | 梯度爆炸 / lr 太大 | 02_exploding |
| `loss` 锯齿、整体不降 + `gradnorm` 乱跳 | lr 太大 / batch 太小 | 03_oscillating |
| `loss` **单调下降**但 `gradnorm` 一路上涨 + 权重不动 | 参数没进优化器 | 04_frozen |
| 层间 `gradnorm` 差 > 2 个数量级 | 深层网络缩放问题 | 01_vanishing |
| 权重直方图 11 个时刻完全重叠 | 冻结 / lr 太小 | 04_frozen |

## 通用排查流程（5 步，2 分钟）

1. **看 `loss/train` 的形状**：水平？锯齿？冲高？平滑？
2. **看 `gradnorm/total`，切 log 轴**：塌陷、尖峰、还是缓降？
3. **看层间差值**：`gradnorm/fc01` vs `gradnorm/fc20`，差几个数量级？
4. **切 `DISTRIBUTIONS` 看 `weights/fc01`**：移动的亮带，还是死竖线？
5. **算 `|grad| / |W|`**：常年 < 1e-5（学不动）或 > 1（不稳），都不正常。

---

## 三个容易误判的地方

1. **`04_frozen` 的 loss 是这批里最好看的一条**（单调下降、没有毛刺），但它是最坏的。
   → 不能只看 loss，必须看梯度/权重。
2. **`01` 和 `05` 的 loss "很稳定"**（恒定 0.693），稳定不等于健康 ——
   ln2 就是二分类瞎猜的损失。
3. **"梯度大"不等于"在学"**：`04` 的 `gradnorm/fc01` 涨到 19，权重却一动不动。
